# 23 — CI on GitHub Actions

Status: ready-for-human

## Scope

`.github/workflows/ci.yml`, on every push to `main`, every pull request, and on demand:

- **backend:** JDK 17 (Temurin, Maven cache), `./mvnw -B -ntp verify`. The integration tests use
  Testcontainers PostgreSQL, since Docker works on GitHub's runners. Test reports are uploaded when
  a test fails.
- **frontend:** Node 22 (npm cache), `npm ci`, `npm test`, `npm run build`.
- **stack** (after both pass):
  1. generate a `.env` with random secrets for this run only (random events off, for
     determinism);
  2. `docker compose up --build`;
  3. wait until nginx serves the UI (200) and the API (401 without a token);
  4. run `scripts/e2e.mjs` against <http://localhost:8088>;
  5. print the container logs and tear everything down.

  This closes the open item of ticket 20: the Docker images and the Compose stack get built and
  checked end to end on every push.
- `mvnw` was committed without its executable bit; it is now set to `100755` in git, otherwise
  `./mvnw` fails on Linux.
- README: a CI badge.

## Acceptance criteria

- [x] Workflow is valid YAML with the three jobs and the right order (parsed with `yaml`).
- [x] Compose accepts the CI `.env` (checked with `docker compose config`).
- [ ] The workflow runs green on GitHub. This needs the first push, which is up to the owner.
