# 32 — Multiple rovers

Status: ready-for-human

## Scope

The backend was already per rover:
- every table keys on `rover_id`;
- uplink sequence numbers are per rover;
- rover-sim's executor and weather loop go over all rover ids;
- sites load by id on both sides.

This ticket adds the second rover and lets the UI choose.

- **Second site** `gale-sim` (Gale Crater, simulated): 64×64, 0–5 m, start (20, 40), seed 2012.
  - It is generated by `TerrainGenerator`, which now takes `<site id> <output folder>` and knows
    both shipped sites (`SHIPPED`).
  - `TerrainLoaderTest` checks that both committed sites match their seeds.
- **Second rover** `Curiosity-sim` (id 2, heading EAST), seeded on both sides with the same id and
  no shared table:
  - mission-control `V13__second_rover.sql` (the rover and its `uplink_sequences` row);
  - rover-sim `V5__second_rover.sql`.
- **UI:**
  - a rover picker in the top bar (shown when there is more than one rover; ⚠ marks a rover in
    safe mode);
  - `RoverSelection` loads `GET /rovers`, remembers the choice per browser, and mounts
    `MissionControl` with `key={roverId}`, so switching starts clean: the other rover's commands,
    photos and stream do not survive;
  - the hard-coded `ROVER_ID = 1` is gone.

## Acceptance criteria

- [x] Two rovers on two sites in both databases; both simulated (one executor and weather loop over all).
- [x] Commands, sequences, telemetry and photos per rover (tested: commands per rover, second site served).

- [x] `./mvnw verify -Plocal-db` green; frontend tests and build green; checked in the browser.
